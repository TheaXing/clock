# 启动失败后的扫码配网与 Wi-Fi 持久化

日期：2026-11-14。状态：2026-11-15 用户确认并授权实施及测试构建。

## 1. 需求与已选择的方案

用户要求：开发板启动时无法连接 Wi-Fi，屏幕显示二维码，手机扫码配置网络；配置成功后，断电或重启仍能读取之前的网络信息并自动连接。

用户已选择“设备热点＋手机网页”，无需安装 App。下述超时、页面细节及存储布局是实现方建议，随本设计一并确认。

## 2. 方案比较

- **设备热点＋本地网页（已选择）**：ESP32-C3 开启临时热点，复用现有 TCP/HTTP 服务；手机先连接热点，再打开本地配网页面。无需云服务或手机 App，但需要两个明确步骤。
- **SmartConfig＋手机 App**：ESP-AT 提供相关命令，但手机需使用 EspTouch 等配套应用，现有项目也没有配套手机端，因此未选择。

凭据存储选用板载 BL24C512 EEPROM。相比只依赖 ESP 自身 NVS，这使 STM32 主程序与 OTA Bootloader 能读取同一份明确版本、可校验、可处理断电的配置。App 与 Boot 的 AT 初始化均明确禁用命令自动写 NVS，避免重试连接反复写入及两处配置不一致。

## 3. 用户操作与启动行为

1. 启动优先读取 EEPROM 中最近有效的 Wi-Fi 配置；尚无有效记录时兼容当前 `CLOCK_WIFI_SSID` / `CLOCK_WIFI_PASSWORD` 默认配置。
2. ESP 初始化完成后先尝试一次连接，连接命令最多等待 20 秒，初始化和状态查询时间另计。没有任何可用配置时直接进入配网；目标网络不可达、密码错误或未获得地址时进入配网。
3. ESP AT 通信本身损坏时显示模块错误并重试初始化，只有热点和 HTTP 服务启动成功才显示可用的配网二维码。
4. 临时热点命名为 `Clock-Setup-` 加设备唯一后缀，使用每次进入配网生成的 WPA2 密码。屏幕首先显示加入热点的标准 Wi-Fi 二维码，同时显示热点名称及手动连接所需信息。
5. 检测手机连接热点并取得地址后，屏幕切换为 `http://192.168.4.1/setup` 的网页二维码；屏幕同时保留可手动输入的地址。手机用系统相机扫码并在浏览器打开，输入目标 Wi-Fi 名称和密码。手机提示热点无法上网时需保持连接。
6. 网页为自包含的中文手机页面，密码输入默认遮盖，可切换显示；不加载 CDN、字体或其他外部资源。首版手动输入 SSID，不增加附近网络扫描。
7. 提交后页面先收到“正在连接”应答，再由网络任务验证新网络。只有 ESP 查询确认已加入目标 SSID 并取得 IP 后，才保存 EEPROM 并回读验证。
8. 成功后显示“配置已保存”，保留热点及结果查询窗口 15 秒，再关闭热点、恢复时钟及正常网络服务。无需强制重启；用户之后重启或断电上电会自动使用此配置。
9. 密码错误、连接超时或保存失败时保留配网入口并显示具体阶段的错误，允许重试；不得把失败候选覆盖为有效配置。保存失败不能显示“已保存”，已有持久化记录保持有效。

两个二维码分别承担“加入设备热点”和“打开配网页面”，不承诺一次扫码同时完成系统 Wi-Fi 切换和浏览器跳转，也不依赖手机自动弹出门户页面。没有手机连接时保持第一步，有手机连接时保持第二步；网页二维码可以重复扫描。热点名、密码及 URL 应可手动使用，便于不支持 Wi-Fi 二维码的手机操作。

范围限定：本次自动配网由启动连接失败触发。正常运行后的短暂掉线保持现有自动重连，不突然切走时钟页面。更换路由器后重启设备即可重新配网。首版保存一个网络，不增加多网络管理、蓝牙、手机 App、云端配网或恢复出厂按键。

## 4. 现有代码接入点

- `app/wifi.c`：从只使用宏常量改为读取启动选定的配置，管理未配置、启动连接、配网、验证、保存、联网等状态；不再因 SSID 宏为空而跳过 ESP 初始化。
- `app/app.c`：`network_loop()` 仍是唯一 AT 事务所有者；配网期间暂停天气、SNTP、MQTT 和 OTA 自动发现等对网络的竞争。候选连接在 HTTP 应答发完并关闭后执行。
- `BSP/ESP_AT/esp_at.c`：增加 AP+STA、AP 地址及 DHCP、热点客户端查询、关闭 AP 的受控接口；服务器地址查询支持 AP 场景。配网中 STA 的 `WIFI DISCONNECT` 不应等同于整个 AP 服务失效；ESP 重启及传输失步仍彻底失效并重建。
- `app/web/clock_web.c`：在同一 HTTP 所有者内增加配网模式和路由，复用连接代次、分段接收、超时及关闭规则；AP 可用不再依赖 STA 已连接。配网模式只开放配网页和状态/提交接口，既有闹钟、OTA 管理接口不在该模式下开放。
- `bootloader/main.c`：恢复联网优先使用同格式 EEPROM 配置，无有效记录时兼容编译默认值。Bootloader 不增加二维码和配网网页；App 已损坏且已保存网络也不可用时，仍遵循原有有线恢复路径。
- `Core/Src/main.c`、EEPROM 驱动及闹钟服务：无论是否开启 OTA，调度器启动前统一初始化 EEPROM 事务锁，所有业务完整读写事务均使用该锁。

## 5. 凭据存储与断电一致性

保留现有闹钟 `[0x0000,0x0800)` 及 OTA `[0x0800,0x1000)` 布局。Wi-Fi 独占 `[0x1000,0x1200)`，两个 256 字节槽位，分别起始于 `0x1000` 和 `0x1100`。

记录使用显式序列化，包含魔数、格式版本、递增代数、SSID/密码字节长度、数据、CRC32 及最后写入的提交标记；不直接落盘 C 结构体。每个槽位前 128 字节为正文，后 128 字节为独立提交页，避免提交时重写正文所在物理页。共享纯 C 存储模块通过读写回调适配 App 与 Boot，具体字节偏移留给实施计划固定并测试。

加载验证版本、长度、CRC 和提交标记，从有效槽中选取最新代数。更新时严格读取两个槽，I/O 失败拒绝覆盖未知状态；使非活动槽提交标记失效后写正文、回读，再最后提交并复查。不在每次连接或重试时写 EEPROM。相同凭据的重复提交无需重复写入。

SSID 为 1–32 字节 UTF-8；密码支持空字符串（开放网络）及 8–63 字节可打印 ASCII 口令，遵循当前 ESP-AT 文档的 63 字节上限，不增加 WEP、企业认证或 64 位十六进制 PSK 支持。拒绝 NUL、控制字符、无效编码、越界及非法长度；以字节数而非屏幕字符数限制 SSID。HTTP 表单编码、AT 参数转义及二维码字段转义分别处理，不能共享错误的转义规则。

EEPROM 事务锁覆盖完整扫描、更新和复查；持锁期间不执行 AT 联网、不等待屏幕、不等待闹钟任务。普通构建也必须使用该锁，修正当前锁仅存在于 OTA 构建中的限制。已有闹钟与 OTA 数据不得被修改或清空。

## 6. 手机接口和网络状态

建议接口：`GET /setup` 页面、`GET /api/wifi/status` 状态、`POST /api/wifi/config` 提交。字段名称和具体错误枚举由实施计划固定。

沿用有界增量 HTTP 解析器与五个连接编号的代次隔离；表单正文容量需覆盖最长合法凭据的百分号编码及会话字段，且不能无界扩容。拒绝重复字段、未知字段、缺少字段、非法百分号编码、错误 Content-Type、不支持的方法及超长输入。

提交仅在配网模式有效，使用当前配网会话标识及现有同源请求头模式，禁止 CORS；状态不返回密码。每次配网的热点密码及会话随机值使用 STM32 硬件随机源，复用 `app/web/web_session.c` 已有的受限等待和错误检查方式；具体接口由实施计划确定。随机源不可用时明确失败，不使用固定公共密码或把设备序列号冒充随机密码。

目标网络加入操作可能使 AP 换信道、手机短时断开，网页需允许重新连接热点、重新查询当前状态；不得把浏览器临时断开当作保存失败。候选任务全局只允许一个，重复请求必须幂等或返回忙碌，不并发连接两套凭据。

AT 连接有明确超时，等待期间保持调度器运行并维持必要 OTA 健康心跳；配网循环仍在安全网络边界调用 `ota_service_network_poll()`，让健康确认能够实际排队、保存，仅暂停 OTA 自动发现。不能让“等待用户配网”阻止 OTA 试运行健康确认。UI、RTC、传感器、按键和本地闹钟继续工作。长期无人配网时服务持续可用，网络硬件异常则有界重建。

## 7. 屏幕与显示并发

屏幕为 240×320。使用黑白二维码、至少四模块白色静区及整数像素缩放；最长热点载荷也需在可用区域内完整容纳，至少按四像素/模块校验可扫描性。首版可使用可容纳的固定长度热点名称及密码，网页地址为固定短 URL。

新增二维码编码和绘制能力，编码器选用适合 MCU 的成熟 C 实现或经过标准向量验证的实现，保留许可证。绘制经现有 UI 队列完成，不从网络任务直接调用 ST7789，也不借用即将释放的栈缓冲作为异步图片资源。

App 维护明确的主页面/配网页面状态及重绘代次。在持有现有显示锁时判断页面模式，阻止时钟、SSID、传感器和天气的局部绘制覆盖二维码。闹钟响铃与现有菜单保持优先，结束后恢复当前配网步骤；配网完成后恢复主页面及缓存值。二维码不必每秒重新编码绘制。

现有小号字体没有中文字形，屏幕首版使用简短 ASCII 提示（如 `1. Join device WiFi`、`2. Open setup page`），手机页面使用中文。新增中文屏幕字体不列入本次范围。
