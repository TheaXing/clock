# 局域网 OTA 后台、构建脚本与开机自动升级

日期：2026-11-14。状态：用户已选择电脑／局域网部署；本增量设计待确认，尚未编写产品代码。

## 1. 意图与已确认范围

用户要求：提供OTA后台网页和构建编译脚本；每次编译后上传后台，设备每次开机自动检查已发布新版本并升级。用户已明确选择“先在电脑／局域网运行，先打通自动更新”。不增加硬件。

本次在现有仓库内开发可在电脑运行的Node服务和静态管理页面，不创建或发布云端Site，不登录或修改OneNET。日常流程为：

`一条命令构建签名包 → 网页上传 → 校验成功后发布 → 时钟开机联网检查 → 新版本排队 → Bootloader认证安装 → App健康确认`。

上传是暂存，发布才使设备可发现；上传文件必须是现有认证`.ota`，不接受裸BIN/HEX或在浏览器内提供发布密钥。离线继续运行时钟；后台服务不可达不导致正常应用无法启动。

以 `docs/superpowers/specs/2026-11-14-single-slot-ota-design.md` 为既有硬件、分区、认证包和日志契约，本文件只描述增量。

## 2. 当前基础与必要迁移

- 基线提交 `1c3bbf7`，现有Node工具只提供单包只读Range服务，启动时固定一个包，没有上传/发布/持久化后台。
- `app/ota/ota_service.c` 已有异步REQUESTED写入、维护准入、延迟复位、三任务心跳和健康确认；`app/app.c` 的唯一网络任务拥有所有应用态ESP命令。
- `esp_at_http_get_bounded()` 适合读取小于1KiB的文本发现元数据。整包下载仍由独立Bootloader完成，不让App直接写应用Flash。
- 当前Bootloader从固定地址重新选包，不核对App选中的版本；只改网页和App不能保证发布切换时下载同一目标，也不能严格防自动降级。
- 因此本版包含Bootloader小改。现有OTA只更新App，启用本协议需通过现有SWD安装新版工厂HEX一次；不能声称已有Boot能无线更新自己。尚未刷过OTA的板直接首次安装新版工厂镜像即可。
- 当前实际OTA配置文件尚不存在，已有OtaDebug/OtaRelease缓存仍指向`build/ota-validation`。新构建脚本必须显式选择实际配置并核对密钥，不静默复用验证配置或生成新密钥。

## 3. 方案选择

| 方案 | 判断 |
| --- | --- |
| App启动联网后检查，Boot负责认证安装 | 推荐并按此细化：保留离线时钟及时启动，复用现有网络所有者、心跳和事务机制 |
| Boot每次上电先联网检查 | 不采用：无网络时要先等待Wi-Fi/HTTP超时，影响正常时钟启动 |
| 后台向设备推送或定时任务代替开机检查 | 不采用：改变用户要求，增加设备在线发现与推送通路 |

“先本地部署”是用户决定；App检查时机、上传后手动发布、目标固定等是本设计提出的实现选择，等待本文件确认。

## 4. 后台网页与运行方式

沿用Node.js 20+内置`http/fs/crypto`及无构建静态HTML/CSS/JS，不新增npm依赖。新增管理服务入口，保留`ota.mjs init/pack/serve`兼容。默认监听`0.0.0.0:8788`，浏览器使用电脑真实IP；设备使用同一稳定电脑地址。服务进程必须在设备检查和下载期间运行。

管理页面包括：

1. 管理令牌输入和进入后台，令牌仅存当前页面内存，退出即清除。
2. 当前发布卡片：版本、文件大小、发布时间、简短包身份。
3. 上传区域：选择或拖入`.ota`，展示传输/校验状态及服务端识别的版本和板型。
4. 版本列表：已上传版本、上传时间、大小、暂存/当前发布状态；允许选择一份已验证包后确认发布。
5. 发布结果与错误：明确区别“已上传”“已发布”；不把下载请求数当成设备安装成功，也不展示虚构的在线设备。

界面不要求输入版本或发布密钥，版本来自包内认证头。摘要详情可展开查看，普通操作以版本和状态为主。首版不做多产品/多用户、设备盘点、远程强制重启或浏览器自动编译。

复用实际`app/ota_key_local.json`的`keyHex`验包、`adminTokenHex`认证管理请求。后台管理与设备网页可以使用同一管理令牌；服务端不会把任何原始令牌、发布密钥返回到页面或公开API。数据目录默认为项目内被Git忽略的`.ota-data/`，可显式改成其他持久目录，不能放在`build/`。

管理API使用`Authorization: Bearer <64位十六进制令牌>`，不使用cookie或URL令牌，不开放CORS；有Origin时严格校验同源。令牌解码后比较摘要使用固定时间比较。静态文件只有明确白名单，不使用任意目录映射，不把密钥或数据目录作为静态资源。首版本地HTTP服务不作为公网部署方案；后续公网部署另行确定TLS和访问控制。

## 5. 上传、发布和持久化

建议新增模块：`tools/ota/release-store.mjs`、`admin-server.mjs`及`admin/index.html/app.mjs/style.css`；CLI新增`admin`命令，提供`scripts/start_ota_server.ps1`启动包装。

| 接口 | 行为 |
| --- | --- |
| `GET /`及固定静态资源 | 后台页面，不包含秘密 |
| `GET /api/releases` | 管理认证后返回列表和当前发布 |
| `POST /api/releases` | 管理认证，`application/octet-stream`，上传并校验`.ota`，只暂存 |
| `POST /api/releases/<packageId>/publish` | 管理认证，原子切换当前发布 |
| `GET <CLOCK_OTA_PATH>` | 当前发布包的兼容二进制别名，供原有手动流程使用 |
| `GET <CLOCK_OTA_PATH>?latest=1` | 设备读取的小型公开发现JSON |
| `GET/HEAD <CLOCK_OTA_PATH>?id=<packageId>` | 不可变版本包，供新版Boot固定下载 |

发现JSON使用固定模式：`available`布尔值；有发布时附`version`正u32、`packageId`32个小写十六进制字符、`header`512个小写十六进制字符（原始256字节已签名包头）。正文限制1024字节。无发布返回`available:false`。不包含任意主机/下载URL，设备只向预先配置的主机请求。

不可变路径由固定`CLOCK_OTA_PATH`加`?id=`和包身份组成；自动模式要求基础路径不超过156字节，以符合已有Boot路径192字节上限。兼容别名继续提供精确Content-Length/Content-Range、强ETag及If-Match；不可变对象发布后字节永久不变，发布切换不会中断已固定版本的下载。查询参数只接受上述两种固定格式，不允许路径穿越或额外参数。

上传最大458752字节，检查声明长度和实际接收长度；明确拒绝缺失认证、错误格式、签名/板型/向量/摘要错误、超大、截断或慢速上传。默认最多两个上传同时处理，每次请求最长30秒，不在验证前更新任何发布状态。相同版本和相同包幂等返回已有记录；相同版本对应不同包时返回409，要求递增版本。

对象以服务端计算的完整包SHA-256保存，不使用上传文件名决定路径；以已有认证packageId建立索引，发现冲突拒绝。写临时文件、完整落盘并验证后再生成可见记录。当前发布指针独立保存，写临时指针、同步并原子重命名成功后才报告发布完成；失败保留原发布。进程重启时验证对象及当前指针一致，损坏指针不能自动把某个未发布上传当作最新版。

首版不提供删除已接收版本的接口，保留设备中断恢复所需包；默认存储上限256MiB，可显式配置，临时上传须计入配额预留。达到上限时拒绝新上传且保持现有版本可下载，不自动清除旧包。最多缓存四个完整包，不能把无限历史包全部永久加载到内存。磁盘人工修改/损坏时拒绝不一致对象，不用新字节冒充旧ETag。

发布可以切回已验证旧版本用于人工恢复；页面明确提示“自动设备不会降级，已开始的安装不取消”。自动设备只处理比自身更新的版本，保留原有管理员或KEY1人工恢复能力。

## 6. 每次开机自动检查

增加`CLOCK_OTA_AUTO_CHECK`开关，OTA构建默认开启，普通独立应用仍禁用。检查在现有唯一网络任务中运行，不增加第二个应用态AT所有者、不阻塞本地初始化。

一次正常启动按以下顺序进行：

1. 启动本地时钟/UI/闹钟，建立原有三任务十秒健康窗口。
2. 当前试启动先完成对应包的CONFIRMED，不允许自动请求绕过或清零TRIAL计数。
3. 首次联网且服务健康后，立即用有界文本HTTP获取`?latest=1`；当前是离线时继续正常时钟，连上后再检查。总共最多三次检查，首次失败后等待5秒、第二次失败后等待15秒再试；第三次失败停止本次启动的自动检查。无发布或不高于当前版本则本次启动检查完成，不写EEPROM。
4. 发现候选时另用明确标注“未认证提示”的结构解析接口检查包头/板型/大小/版本/公开身份一致；不能把已有trusted当前镜像读取接口用于网络授权，更不能把发布HMAC密钥重新放进App。
5. 当前日志必须为与当前安装描述匹配的CONFIRMED；本地编辑、保存、响铃/贪睡时延期，稍后在同一次启动重试准入。存储worker持锁后重新验证当前日志、版本差和目标身份，再提交自动REQUESTED。
6. 自动REQUESTED保存完整候选原始包头，人工REQUESTED仍全零。只有持久化及回读成功后才沿用现有两秒宽限复位。

自动检查的次数、网络失败和无新版结果放在RAM，不逐次写EEPROM。设备网页/串口增加最近检查结果（等待联网、检查中、已是最新、设备忙、已排队、后台不可达），不暴露凭据。后台本身不假装知道设备是否最终安装成功。

为避免服务器不可达导致“回到旧App后再次自动复位”的循环，必须区分新的正常上电/外部复位与OTA软件复位后的失败回退。失败回退当次只报告结果，不再次自动提交；下一次正常开机可重新检查并重试同一候选。若上次自动REQUESTED保留且Boot记录了明确预检错误，只有新的正常启动允许重新提交该失败自动请求；未失败的REQUESTED、人工全零REQUESTED、INSTALLING、TRIAL均不能被自动请求覆盖。实现时用现有RCC复位原因的受控快照及明确清除规则，补充独立回归；无需新硬件或新增高频持久化计数。

## 7. Bootloader目标固定与版本保护

保持Flash分区、256字节认证包、EEPROM v1布局和原有安装器接口不变。不向日志保留字段偷塞新标志。

- `REQUESTED.manifest`全零：现有人工语义，读取当前发布别名，可由管理员有意选择旧版。
- `REQUESTED.manifest`非零：自动固定候选。先对保存包头做完整HMAC认证，存在完整认证的旧镜像时还须验证候选版本严格更高，再派生固定主机下的`?id=<packageId>`。旧镜像已经损坏而不可用时，允许以认证的已保存目标恢复，不因缺失版本基线永久阻塞修复。网络返回包头须与保存包头精确一致，再开始INSTALLING；未经认证的App发现信息无权触发擦除。
- 已经`INSTALLING`：manifest就是已经获准的固定目标，按其不可变身份重下；不再从当前发布别名重新挑选，也不把它一概当自动请求再次做降级判断，保留人工恢复已获准目标的语义。
- 人工请求或空白恢复首次从别名拿到认证包头后，也将后续正文固定到不可变路径；后端保留别名以兼容旧Boot读取。
- 保留扇区7先失效、INSTALLING日志提交后才擦除、完整Flash摘要通过后才提交footer、TRIAL次数提交失败锁存拒绝启动、三次未确认阻止同包自动重装等全部不变量。

KEY1强制恢复与当前发布别名保留；自动升级不降级，不重复安装相同版本。新Boot必须支持新后台；旧Boot仍可手动从兼容别名更新App，但不应声称具备目标固定的完整自动协议。

## 8. 一条构建命令

新增`scripts/build_ota.ps1`，拟定日常命令：

```powershell
.\scripts\build_ota.ps1 -Version 2 -Configuration Release
```

参数包括显式可选`-OtaConfig`、`-KeyFile`、`-OutputDirectory`、`-ActiveBuzzer`及首次部署用`-Factory`，版本为必填正u32。普通路径默认实际`app/ota_config_local.h`及`app/ota_key_local.json`；缺少即清楚报错，不偷偷选验证配置或重新init。

脚本流程：

1. 校验真实配置、密钥JSON、发布密钥一致性、版本/路径范围；不打印秘密。
2. 在被忽略的构建目录生成私有配置副本，将版本统一为`-Version`，不改用户原私有配置，不只依赖CMake缓存。
3. 显式调用现有`build.ps1 -Ota -OtaConfig <生成副本>`并透传蜂鸣器选项。
4. 对实际App/Boot二进制执行现有向量、容量及秘密隔离检查。
5. 使用同一版本和原发布密钥签出`.ota`，生成公开报告；`-Factory`时另生成组合工厂HEX。
6. 产物进入明确的新版本目录，已有目标拒绝覆盖，失败不留下可被误上传的半包。终端最后只显示包路径、版本、大小和公开摘要。

设备后台网页上传脚本输出的`.ota`。脚本不自动上传或发布，以保持用户要求的网页上传流程。使用说明给出首次配置、一次新版工厂安装、后台启动、v2/v3发布与重启检查。

## 9. 验证与交付

后端测试：认证/同源、坏包/错板型/超量/中断/超时上传、重复版本冲突、发布失败保留旧指针、并发发布、重启持久化、存储上限、不可变Range与发布切换、原别名兼容和静态路径限制。

设备主机测试：无发布、同版/旧版、乱序/缺失/超长JSON、头与身份不符、新版准入、健康未确认、维护忙与后续准入、只用网络所有者、最大检查次数、无更新零EEPROM写、请求ACK丢失不复位、失败软件回退不循环、下一次外部开机可重试。

Boot回归：伪造提示无法越过HMAC、候选版本不高拒绝、发布切换仍安装原目标、INSTALLING重试固定旧包、人工降级保持、现有全部断电/日志/TRIAL保护仍通过。

构建脚本测试：缺配置、密钥不一致、旧验证缓存、版本同步、ActiveBuzzer传递、编译失败无成品、已有产物不覆盖；用隔离测试配置构建普通/OTA Debug/Release，打包与实际二进制秘密扫描。

页面使用真实本地后台做浏览器验收，检查登录、上传/错误反馈、版本列表、发布确认、刷新持久化和窄屏可用；不能用纯模拟页面冒充上传成功。

交付源代码、完整测试、构建/启动脚本、中文说明和本地预览；不自动烧录、不修改选项字节，不公开部署。实板“新版工厂安装→上传发布v2→正常开机自动升级→断网保持时钟→后台切版不混包→恢复下载”仍由用户上板验收，不把主机测试当作实板结果。
