# 单应用分区 OTA 与 Bootloader 恢复下载设计

日期：2026-11-14。状态：用户已确认；代码、主机测试和构建已完成，实板验收待执行。

## 1. 用户决定与目标

用户已选择“单应用分区 OTA＋Bootloader 恢复下载＋EEPROM 状态日志”，要求在现有时钟项目上设计并实现，不增加硬件，并明确确认本设计、授权完成代码、测试和构建。实现阶段的重要修复和技术决定记录于执行账本。

目标是让现有 STM32 时钟通过 ESP32-C3 无线更新应用；下载或安装中断后，受保护的 Bootloader 仍可独立联网重新下载。首版中断后重新下载整个包，不承诺断点续传；设备没有旧镜像备份，不承诺离线回滚。升级期间主应用停止运行，RTC 保留走时。

交付完整的 Bootloader、重定位应用、公共升级协议和事务日志、应用网页触发与状态、电脑端打包及只读固件服务器、自动测试和首次安装/实板验收说明。仅修改和验证仓库文件，不自动烧录、不修改选项字节、不登录真实云平台、不增加或改接硬件。

## 2. 已核实的项目约束

- `Clock_CubeMX.ioc` 指定 STM32F407VET6；内部 Flash 确定为 512 KiB，范围 `[0x08000000,0x08080000)`。禁止使用 CMSIS 头文件中覆盖其他容量型号的通用 `FLASH_END` 作为擦写上限。
- 当前 GCC 应用从 `0x08000000` 链接；已有构建产物 Release 259204 字节、Debug 308012 字节，仅作为容量估算，最终重新编译测量。
- SPI2 服务 LCD；不存在已接入的外部固件存储器。RAM 不足以缓存整包。
- BL24C512 为 64 KiB、128 字节页，I2C1 PB6/PB7、100 kHz、7 位地址 0x50。闹钟日志占 `[0x0000,0x0800)`。
- EEPROM 驱动当前只保护单次 HAL 调用，闹钟保存任务拥有业务日志；增加另一个独立写入任务会造成事务交错，必须增加统一互斥。
- ESP32-C3 MINI-1、ESP-AT 4.1.1 是项目记录中的模块和版本；实板仍应记录 `AT+GMR`。USART2 PA2/PA3，115200、8N1，无硬件流控，应用使用逐字节中断接收。
- 当前 HTTP 下载路径是 2048 字节文本缓冲，拒绝 NUL，不能直接下载固件；当前 ESP 驱动依赖 FreeRTOS，不能整体链接进裸机 Bootloader。
- 工程未定义 ESP EN/RST 控制引脚。Bootloader 尝试串口同步和 `AT+RST`；ESP 完全失去 AT 响应时，需要用户给整板重新上电，软件不能承诺代替硬件复位。
- 遵守 `AGENTS.md`、`docs/CODING_STYLE.md`；新增可复现 C 测试放在已跟踪的 `BSP/OTA/tests/`，不只放在被忽略的根 `tests/`。

## 4. Flash 与构建布局

| 区域 | 范围，末地址不含 | 大小 | 擦除扇区 |
| --- | --- | --- | --- |
| Bootloader | `[0x08000000,0x08010000)` | 64 KiB | 0～3 |
| App 代码及资源 | `[0x08010000,0x0807FF00)` | 458496 字节 | 4～7 的主体 |
| App 安装描述及提交标记 | `[0x0807FF00,0x08080000)` | 256 字节 | 7 的末尾 |

Bootloader 独立 CMake 目标，固定 `-Os`，不包含 FreeRTOS、LCD、天气、OneNET 或 Newlib 浮点输出。链接器限制其 64 KiB 上限，超限即构建失败，不静默挤占 App。使用独立启动/中断文件、SysTick 毫秒时基和有界 HAL/寄存器适配层，不链接应用 TIM7 时基。

保留原有 Debug/Release 作为 `CLOCK_OTA_ENABLED=OFF` 的独立应用构建，仍从 `0x08000000` 启动。新增 OtaDebug/OtaRelease 预设及构建脚本显式开关；`ON` 时应用链接起点改为 `0x08010000`、可用长度 458496，并构建独立 Bootloader，同时设置向量表基址，保留原有 SRAM/CCM 布局和 GBK 执行字符串设置。OTA 构建缺少发布密钥或恢复服务器配置必须立即报错，禁止偷偷回落为未认证版本。

普通和 OTA 的 Debug/Release 都须验证；IAR 链接布局需显式区分独立与 OTA 构建，未配置的模式应报错或不提供该模式，不能继续生成地址错误的 OTA 包。RGB 冒烟构建仍可独立构建，但不会作为正常 OTA 升级包发布。

常规输出包括 Bootloader、App 的 ELF/HEX/BIN；打包工具额外输出无线升级 `.ota` 和首次 SWD 安装的工厂 HEX。工厂 HEX 包含 Bootloader、重定位 App、经认证的安装描述；不包含 EEPROM 闹钟数据。

## 5. 升级包与固件真实性

首版使用局域网 HTTP 搬运固件，以 HMAC-SHA256 验证发布者，以 SHA-256 验证完整镜像。校验通过仅指包和镜像合法，不代表业务逻辑无缺陷。密钥属于现有硬件上的软件凭据，不构成安全芯片等级的物理防护。

使用显式小端序固定 256 字节包头，随后紧跟原始 App BIN，不通过 C 结构体内存布局序列化：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 8 | 魔数 `CLKOTA1` 加 NUL |
| 8 | 4 | 格式版本 1 |
| 12 | 4 | 包头长度 256 |
| 16 | 4 | App 地址 `0x08010000` |
| 20 | 4 | 镜像长度，`0x188..458496` |
| 24 | 4 | 无符号整数固件版本，用于识别和显示 |
| 28 | 4 | 标志，首版固定为 0 |
| 32 | 32 | 目标板标识 `Clock_CubeMX-STM32F407VE`，剩余字节补零 |
| 64 | 32 | 原始 App BIN 的 SHA-256 |
| 96 | 16 | 包身份，取前 96 字节 SHA-256 的前 16 字节 |
| 112 | 80 | 保留，全部为零 |
| 192 | 32 | HMAC-SHA256，认证包头 `[0,192)` |
| 224 | 28 | 保留，全部为零 |
| 252 | 4 | `.ota` 中为 `0xFFFFFFFF`；内部安装描述最后提交为 `0x3141544F` |

HMAC 中被认证的 SHA-256 绑定全部 App 字节。比较认证值使用固定时间比较。错误板型、版本格式、地址、长度、保留位、HMAC、正文摘要、向量均拒绝。服务器不得依靠修改包头来替换已发布文件。首版允许操作者发布经过认证的较旧版本以远程修复，不宣称防降级。

升级发布密钥和网页触发令牌为两份不同的 32 字节随机值。生成到 Git 忽略的本地文件，不在代码中放生产默认密钥，不记录到日志，不内嵌网页、不由状态接口返回。未配置发布密钥时只能构建原地址独立应用，Bootloader/OTA/工厂镜像构建必须报错；已经正确配置发布密钥而缺少管理令牌时，仅禁用网页触发，已认证时钟仍可启动，KEY1 和配置的恢复下载仍可使用。打包命令拒绝使用缺失或全零密钥。软件参考实现需用标准 SHA-256/HMAC 测试向量和电脑端实现交叉验证。

实现审阅后的凭据隔离约束：发布密钥仅进入 Bootloader，不进入可下载 App。App 只通过明确标记的 trusted 元数据接口读取已经由 Boot 完整认证的安装描述，该接口不能授权 Boot 或安装器。管理令牌仅以解码后32字节的 SHA-256 验证值进入 App，工具生成 `CLOCK_OTA_ADMIN_TOKEN_SHA256_HEX`；原令牌保留在本地 JSON 供操作者使用。真实构建产物必须通过发布密钥与原始令牌缺席扫描。

## 6. EEPROM 日志、并发和掉电规则

| 范围 | 用途 |
| --- | --- |
| `[0x0000,0x0800)` | 保留现有闹钟双槽日志 |
| `[0x0800,0x0C00)` | OTA 槽 A，1024 字节 |
| `[0x0C00,0x1000)` | OTA 槽 B，1024 字节 |
| `[0x1000,0x10000)` | 仍未分配 |

OTA 槽体为 384 字节：128 字节状态头和完整 256 字节目标包头。目标尚未获取时包头全部为零。状态头显式小端序，字段依次为：`OTAJ` 魔数 u32、模式版本 u16=1、头长度 u16=128、记录长度 u32=384、代数 u32、CRC32 u32、状态 u32、试启动次数 u32、最后错误 u32、包身份 16 字节、标志 u32=0，其余字节为零。CRC32/ISO-HDLC 覆盖槽体 `[0,16)` 和 `[20,384)`。

独立提交页位于槽内 `0x380`，即绝对地址 `0x0B80`、`0x0F80`。前 16 字节为 `OTAC`、代数、记录 CRC、反码代数，其余字节为零。切换槽时先清除并回读提交页，再分页面写入并回读槽体，最后写入并回读提交标记，随后重新读取两个槽确认最新有效记录。任一步失败均返回失败或结果不确定，不把“发出写命令”当作持久化成功。代数使用可检测冲突和回绕的比较规则；同代不同内容、半范围歧义均报告损坏。

只有两个槽整体全为 `0xFF` 才算 EMPTY；任一槽读取失败算 IO_ERROR，不能当成空白。一个有效槽加一个撕裂槽可选择有效槽，但两个槽均无效且非空白算 CORRUPT，不自动覆盖猜测的基线。EMPTY 时只有完整验证工厂安装描述和实际镜像后才能建立 TRIAL 初始记录，不能仅凭完整性把业务健康状态自动记为 CONFIRMED。

采用 `IDLE/REQUESTED/INSTALLING/TRIAL/CONFIRMED/FAILED` 状态。只在重要状态转换时写 EEPROM，不逐数据块记录下载进度。日志记录不能单独证明 App 完整；每次跳转仍须独立验证内部安装描述和全部镜像。

应用增加全 EEPROM 设备互斥；闹钟事务与 OTA 事务从扫描到提交复查全程持有同一事务锁，底层单页传输仍有界并让出处理器。统一锁在调度器启动前创建，失败时拒绝持久化请求并保留已确认配置；禁止在 ISR 或调度器已暂停时等锁。采用明确的锁顺序，不在持有 EEPROM 锁时等待闹钟 owner 或网络回复。Bootloader 使用同样的纯 C 日志模块和裸机 I2C 适配器，无 RTOS 依赖。

## 7. Bootloader 决策与恢复

### 正常启动

先读取完整安装描述并验证 HMAC、镜像 SHA-256 和向量；只有验证通过才能启动。MSP 必须 8 字节对齐且 `0x20000000 < MSP <= 0x20020000`；复位向量必须为 Thumb 地址，去最低位后的地址必须在 `[APP_BASE+0x188, APP_BASE+image_size)`。不用只检查前两个向量的方式自动认领 App。

工厂安装由打包工具提供明确的已认证描述，允许在 EEPROM 空白时验证后建立 TRIAL 初始记录。EEPROM 损坏/掉线不会把未认证 Flash 自动标成有效。存在已认证且完整的应用、且没有已知强制恢复条件时，可启动正常应用并把 EEPROM 故障报告为 OTA 不可用；不把日志读取失败记作健康确认。涉及擦写的流程必须先成功提交日志。没有可信应用时留在恢复状态。

跳转前停止 SysTick、关停和清理 Boot 使用的外设/中断、清除 NVIC 使能及挂起位和 PendSV/SysTick 挂起状态，恢复 CONTROL/BASEPRI/FAULTMASK 等复位式状态并设置 VTOR。最后通过汇编尾段装载 MSP、恢复 PRIMASK 以允许应用时基中断，再跳转到 Reset_Handler；换栈后不再调用 C 函数。不复位 RTC 备份域，应用自己完成 SystemInit 和外设初始化。

KEY1（PA0、低有效）在上电阶段稳定按住约 2 秒可强制恢复下载；遵守已有 H1 跳帽要求，不修改接线。首次实现用串口输出恢复状态，不把 LCD 驱动搬进 Bootloader。

### 接受升级与安装

1. App 网页请求先校验会话、独立管理令牌和当前忙状态，再交给 OTA 状态机；网络回调不直接写 EEPROM。POST 的 202 仅表示请求已进入队列，并返回本次启动有效的请求编号。
2. 与闹钟保存/本地编辑/响铃冲突时返回忙，由闹钟 owner 原子确认维护状态，阻止新的配置提交后才开始 OTA 日志事务；已有保存结果不明确时不复位。客户端 GET 轮询区分 queued/saved/failed，只有提交并回读 `REQUESTED` 后显示“升级请求已保存，即将重启”。
3. 成功提交后给网络响应预留 2 秒宽限，再由网络任务完成响应/关闭连接并执行 `NVIC_SystemReset`；不依赖浏览器必须读到结果，响应丢失不能撤销已经持久化的任务。失败时释放维护状态，保持旧应用运行；重复请求按当前状态去重。
4. Bootloader 自行恢复 ESP、连接 Wi-Fi、读取配置的恢复入口并获取包头。在包头认证及 HTTP 身份检查通过前，不修改 App。旧 App 仍完整且尚未擦写时，网络失败可保留请求并在有限等待后回到旧 App。
5. 先把目标包身份、包头和 `INSTALLING` 提交到 EEPROM 并回读成功。擦除顺序必须先扇区 7，确认原安装描述已失效，再擦除扇区 4～6；擦写 API 硬性拒绝 Bootloader 地址、越界和跨区域请求。
6. 分块获取数据、关闭连接、消耗 AT 尾部并排空串口，然后按字节长度写入 App 并回读校验；最后不足一个编程单元的尾部按 `0xFF` 填充，摘要只计算实际长度。
7. 全部写入后，清理 Flash 指令/数据缓存，重新从内部 Flash 计算完整 SHA-256 并验证向量。通过后写安装描述前 252 字节并回读，最后写提交标记，再验证描述、HMAC、摘要和向量。
8. 成功提交 `TRIAL` 后启动应用。应用本地 UI、闹钟服务、网络任务创建成功且稳定运行 10 秒后异步提交 `CONFIRMED`；确认仅适用于与当前安装描述包身份一致的 TRIAL，不得覆盖另一个 REQUESTED/INSTALLING 任务，不以连接到互联网作为确认条件。

“稳定运行”的实现判据是时钟、UI、闹钟所有者三个真实任务的持续新鲜心跳，时钟/UI阈值2500毫秒、闹钟1000毫秒；任意任务过期后重开完整十秒窗口，存储确认前再次检查。已知 TRIAL 计数提交失败时本次 Boot 锁存禁止跳转，仅新安装完整提交成功后解除；不能通过后续损坏日志降级旁路。三次失败后自动恢复不得重装相同认证包来清零次数，物理 KEY1 强制恢复除外。

每次未经确认的启动记录试启动次数；连续 3 次复位仍未确认时留在恢复模式。首版不新加系统看门狗，不承诺任意死锁能自动复位；程序卡死时按 RESET 或重新上电，KEY1 可强制恢复。安装描述已完整提交但 EEPROM 后续提交中断时，可对同一目标重新验证并完成日志转换，不能再次信任旧的 `CONFIRMED` 摘要。

### 中断和异常

- 擦写前失败：只要旧应用安装描述及全镜像验证通过，仍可使用旧版。
- 首次擦除后断电：安装描述无效，下一次启动不能进入半成品 App；使用 EEPROM 目标身份和恢复入口重新下载整包。
- 中途网络断开：停止擦写，持续有界重连；每次重试重新认证包并从头安装，不拼接不同版本。
- 服务端包已变化：不得继续混合下载；只允许在重新认证新包、提交新目标状态后完整重下。没有可认证包时等待，不能降级为不校验。
- EEPROM 写入失败：不得开始破坏旧 App；已破坏时保留 Bootloader，等待存储恢复或通过既有 SWD 维护。不能把网络重试误报为 EEPROM 已修复。
- 没有可信包、网络或可写日志时，恢复状态保留串口错误信息并退避重试，不宣称可恢复正常时钟。

## 8. 独立联网与 HTTP 子集

Bootloader 共用被忽略的本地 Wi-Fi 配置，并新增被忽略的 OTA 本地配置，指定固定服务器主机、端口、包路径、发布密钥和触发令牌。恢复入口不从正在更新的 App 中读取，也不接受网页传入任意 URL。首版使用现有电脑/服务器上的局域网 HTTP 服务，不修改 OneNET 产品物模型和云端权限。

裸机传输层使用 USART2 轮询、有限超时、二进制定长接收。启动时处理 ESP 可能仍处于 CIPSEND/MQTT/证书输入窗口的情况，采用有上限的填充/排空及 `AT+RST` 同步；异常或复位后重新初始化，不继续发送不确定命令。配置 `ATE0`、`SYSSTORE=0`、station、`CIPMUX=0`、`CIPDINFO=0`、`CIPRECVTYPE=1`。

用 TCP 构造 HTTP GET 和 Range，每次镜像正文最多 4096 字节，`CIPRECVDATA` 每次最多拉取 256 字节；NUL、CRLF、`OK`、`ERROR`、`+IPD` 在载荷内都是普通数据。`+IPD` 长度是缓存快照，不能累加；远端关闭时仍需先读尽已缓存数据。每次完整关闭/排空后才允许 Flash 擦写，避免 F407 单 bank 暂停取指造成 USART 溢出。

首个请求获取包 `[0,255]`，后续请求获取包中偏移 `256+image_offset` 的最多 4096 字节。服务器固定返回 HTTP/1.1 206，要求唯一的 Content-Length、Content-Range 和强 ETag；请求包含 `Accept-Encoding: identity`、`Connection: close`，后续请求包含 `If-Match`。强 ETag 为 `.ota` 文件 SHA-256 的 64 位十六进制字符串，加双引号；总长度必须为 `256+image_size`。

严格拒绝 200、重定向、chunked、压缩、多段 Range、重复关键头、长度溢出、短正文、超量正文和 ETag 变化。头部总长上限 2048 字节，单行上限 256 字节；命令与网络等待有界，连接/读请求最长 15 秒、Wi-Fi 加入最长 30 秒。无可信 App 时按 2/4/8/16/30 秒退避持续恢复；旧 App 尚完整时单次请求预检等待总预算 60 秒，超时可返回旧应用。

HAL 超时依赖的时基不能因主动关中断而失效；Flash 操作不沿用应用 TIM7 中断。Flash 等待采用独立且经过测试的有界机制，禁止在永久停住的 SysTick 上自旋；擦写开始前确保 UART 空闲，并在擦写后显式恢复 UART 错误状态和缓存。

## 9. 应用与电脑端入口

应用增加 `GET /api/ota` 查询：是否启用、当前版本/包身份、升级状态、最后错误、是否正在保存、请求编号。返回值不包含密钥、令牌或 Wi-Fi 密码。

增加 `POST /api/ota`，沿用受限表单和会话防串启动机制，正文只包含 session 与独立管理令牌，长度在当前 384 字节上限内。会话值用于并发控制，不当作认证。未配置返回 503，认证失败返回 403，保存/本地编辑/响铃冲突返回 409，接受排队返回 202；客户端轮询持久化状态，不能把 202 显示成升级成功。管理令牌由操作者在页面输入，仅驻留本页内存，不存 localStorage，不回显、不随状态 GET 返回。

现有闹钟网页增加“固件升级”区域，显示版本、升级进度的阶段和错误说明、管理令牌输入及确认按钮；升级开始后提示设备暂时离线，回来后重新获取会话和实际版本。恢复阶段通过电脑服务器日志和串口观察，不虚构浏览器能持续连接 Bootloader。

新增 `tools/ota/`，不放宽现有 OneNET 工具的 loopback 限制。Node.js 20+ 内置 crypto/http/fs 即可完成密钥初始化、严格打包、工厂 Intel HEX 合成、只读包服务器和主机测试，不新增 npm 依赖。服务器只暴露固定配置的包，启动时读取并验证包、冻结内存快照，提供 GET/HEAD/单 Range、206/416/412、强 ETag 和准确长度；不得读取任意请求路径、暴露密钥或顺带代理 OneNET 凭据。

打包工具验证向量地址、长度和目标平台；输出认证包、带安装描述的首次安装 HEX，以及不含秘密的大小/版本/摘要报告。首次安装必须使用 Bootloader 与重定位 App 组合工厂镜像，禁止只刷重定位 App 后期待芯片从原入口启动；说明书明确区分旧版整片 App、工厂镜像与无线包。

## 10. 模块边界与验证

建议模块：`BSP/OTA/` 保存公共布局、SHA256/HMAC、包头/向量验证、EEPROM 日志和可测试安装状态机；`bootloader/` 保存裸机启动、HAL 适配、UART/AT、HTTP Range 下载与安全跳转；`app/ota/` 保存请求、健康确认与日志任务；`tools/ota/` 保存打包、只读服务与命令行入口。

HTTP、包头、日志和安装状态机依赖注入 I/O，主机测试可在每次 EEPROM 页写/提交、每次 Flash 擦除/编程边界模拟断电。实现计划必须给出这些模块的确切接口，再开始写生产代码。

自动验收至少包括：

1. 标准 SHA-256/HMAC 向量、电脑与 C 实现交叉验证；任一受认证字段或镜像字节改变均拒绝。
2. 包头边界、错误地址/板型/大小、整数溢出、MSP 顶部合法值、Thumb 与精确镜像范围。
3. EEPROM 空白、损坏、I/O 失败、同代冲突、回绕；对每个写入边界断电，旧已提交状态可恢复，未提交状态不能触发擦除。
4. Flash 擦写永不触及扇区 0～3；原 footer 必须先失效；任意安装断点都不能启动不完整 App。
5. HTTP/AT 任意分包、二进制特殊字节、异步通知、ESP 复位、CIPSEND 输入窗恢复、超时、短包/超包、ETag/Range 不匹配。
6. 请求令牌/会话/忙状态、持久化失败、响应丢失、重复请求、健康确认和三次未确认恢复。
7. 打包、工厂 HEX 地址和重定位检查、服务端 Range/If-Match/冻结快照/路径限制。
8. 现有跟踪 BSP 测试、当前工作区全套主机测试、App Debug/Release、Bootloader 和必要冒烟配置编译；检查 ELF 向量、地址、实际 Flash/SRAM/CCM 占用与密钥忽略规则。

实板必须另行完成：首次 SWD 安装、正常离线启动、真实 ESP 被动二进制下载、升级前后版本/闹钟保持、App 向量交接、各阶段断电重下、网络中断、错误包、KEY1 强制恢复、ESP 整板断电恢复。主机测试和编译通过不代表这些实板项目已通过；本次不自动执行烧录或断电。
