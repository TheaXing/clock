# 第一阶段：本地闹钟操作与上板验收

本阶段在原时钟、南京天气、AHT20 温湿度和 FreeRTOS 基础上加入蜂鸣器、三个按键、8 组闹钟与 BL24C512B 掉电保存。手机网页控制留到下一阶段。本文件描述实际固件行为；主机测试和编译不能替代以下实板验收。

## 硬件核对

按 `原理图 V1.2.6.pdf` 接口实现：

| 功能 | 接口 | 核对要点 |
|---|---|---|
| 蜂鸣器 | PC7，TIM3_CH2，约 2.73 kHz PWM | 经 Q1 三极管驱动，HIGH 导通，停止时强制 LOW；检查主电源/5V |
| KEY1 / K1 | PA0 | 低电平按下；H1 可连接 ESP_WAKE_MCU 与 PA0。用户焊接板已验证按键可用，保持现有状态；出现干扰时再核对这条共用信号 |
| KEY2 / K2 | PC4 | 低电平按下 |
| KEY3 / K3 | PC5 | 低电平按下 |
| EEPROM | I2C1，PB6 SCL / PB7 SDA，100 kHz | BL24C512B，64 KiB、128 字节页；A0/A1/A2/WP 接地，7 位地址 0x50 |
| AHT20 | 原 I2C2，PB10 / PB11 | 与 EEPROM 分开，不改原连接 |
| ESP32C3 | 原 USART2，PA2 / PA3 | 保留原 AT 固件与通信 |
| RTC | 原 LSE 与 VBAT | CR2032 保持日历；断主电时电池不能给蜂鸣器供电 |

原理图蜂鸣器标注不能唯一确定实物是有源还是无源。默认提供 PWM；若实物确认是有源蜂鸣器，可构建 GPIO 驱动版本：

```powershell
.\scripts\build.ps1 -Configuration Release -ActiveBuzzer
# 恢复默认 PWM 版本：
.\scripts\build.ps1 -Configuration Release
```

## 烧录与第一次使用

1. 默认完整功能构建：`.\scripts\build.ps1 -Configuration Release`。
2. 烧录 `build/Release/Clock_CubeMX.hex`；BIN 对应起始地址 `0x08000000`。Debug 产物在 `build/Debug/`。
3. USART1 打开 115200、8N1，启动版本应为 `v1.2-ALARM`。检查 `Alarm storage boot result`、原有 `Workqueue running`、AHT20 和联网日志。
4. 新 EEPROM 或无有效记录时，8 组闹钟全部禁用。默认编辑值为 07:00、周一至周五、响铃 60 秒、贪睡 5 分钟，启用后才会触发。
5. 正常启动进入主页面后，网络任务在后台连接；断网不阻止按键、菜单和本地闹钟。首次 EEPROM 扫描期间按键服务尚未启动。

菜单使用现有 ASCII 字库，按键简称 K1/K2/K3 对应丝印 KEY1/KEY2/KEY3。约 30 ms 消抖；按住约 0.8 秒产生一次长按，松开不会再触发短按。按住上电的键需先松开。

## 按键操作

| 所在页面 | K1 短按 | K2 短按 | K3 短按 | 长按操作 |
|---|---|---|---|---|
| 主页面 | 打开闹钟列表 | — | 打开闹钟列表 | K2：10 秒后试响 |
| 闹钟列表 | 切换选中闹钟启用状态并保存 | 下一组，1～8 循环 | 编辑选中组 | K2：手动校时；K3：回主页面 |
| 编辑闹钟 | 下一字段 | 增加/切换 | 减少/切换 | K1：保存；K3：放弃草稿回列表 |
| 手动校时 | 下一字段 | 增加 | 减少 | K1：应用 RTC 时间；K3：取消 |
| 响铃、贪睡等待、试响等待 | 停止并取消全部等待 | 响铃时贪睡 | — | K1/K2 对应停止/贪睡 |

响铃或等待界面优先于菜单，取消后回到原页面。普通闹钟已处于贪睡等待时，再按 K2 保持原截止时间；试响等待时按 K2 改为从当前起再等 5 分钟。保存过程中编辑键暂时不接受，停止/贪睡仍可用。

编辑字段包含启用、小时、分钟、模式、日期或重复星期、贪睡分钟、响铃秒数。`WEEKLY` 按选择的星期重复；`ONCE` 仅在指定年月日触发。切换到 ONCE 时带入当前有效日期，请自行确认日期在未来。周重复至少保留一天；贪睡可调 1～30 分钟，响铃可调 5～600 秒。设置最后需长按 K1，看到 `Saved` 才表示写入和校验成功；仅改变屏幕草稿不会生效。

`Save failed` 时保留当前运行配置与编辑草稿，可排除故障后重试。列表直接开关也只有保存成功才改变运行状态。EEPROM 恢复后，保存会重新读取有效配置，仅合并本次修改的一组，保留其他组。

## 推荐的上板顺序

### 1. 先做 10 秒试响

在主页面长按 K2，出现 `TEST ALARM PENDING`；约 10 秒后显示 `ALARM RINGING`，蜂鸣器每 0.5 秒响/停交替。K1 应及时停止并恢复原页面。再次试响，验证 K2 贪睡、K1 取消等待；不操作时响铃 60 秒自动停止。

该试响不写 EEPROM，也不需要 RTC 时间有效，优先用于区分蜂鸣器、按键和日历配置问题。若界面响铃但无声，核对 PC7 PWM、Q1、主电源、蜂鸣器极性和类型；不要先改闹钟引擎。

### 2. 校时与一组真实闹钟

联网后核对北京时间、日期和星期。离线首次使用可从列表长按 K2 手动设置年月日时分秒，长按 K1 应用，查看 `Time set`。默认 2000 年或 RTC 不可用时，不触发日历闹钟，但试响仍可运行。联网 SNTP 会重新校准 RTC，人工校时试验建议先断开 AP。

编辑第 1 组：启用，设为 ONCE，日期为今天，时间为当前之后 2～3 分钟，响铃 10 秒，贪睡 1 分钟；长按 K1 保存，再长按 K3 回主页面。串口应有 `Alarm configuration saved`；到分钟边界应出现 `Alarm started mask 01`。验证自动停止、K1 停止、K2 贪睡约 1 分钟后重响。

启用或校时到已经过去的时刻不会立即补响；大幅校时后从下一个正常时间边界开始。当天已经过去的 ONCE 闹钟也不会在第二天补响。

### 3. 八组、重复与界面并发

- 配置第 1 与第 8 组同一分钟，响铃时间不同，确认同时触发、屏幕两组编号完整，K1 停止全部，K2 各按自己的贪睡时间恢复。
- 将 8 组设为同一分钟，检查 `mask ff`、列表完整显示 8 组、同时响铃无卡死。不要只检查第 1 组。
- 分别验证工作日、周末、ONCE 日期；从 23:59 跨到次日，检查日期、星期和触发条件。测试日期应明确落在所选星期。
- 打开菜单保持至少 2 分钟，期间原天气/温湿度日志应继续更新，页面不被主时钟覆盖；退出后应立即恢复最新已采集数据。菜单打开或正在保存时，到点仍须响铃。
- 校时回拨到同一组最近已经响过的日期/时刻不应重复响；将误设的未来年份校回正常年份后，后续未响过的日期仍应正常触发。

### 4. 掉电与保存故障

- 保存第 1、4、8 组不同的时间/星期/启用状态。按 RESET，逐组核对；断主电再上电，再核对。8 组配置不依赖 VBAT。
- 有有效 CR2032 时验证断主电后日历继续；无 VBAT 时先重新校时，不能把时间丢失当作闹钟配置丢失。
- 改动一组后，在 `Saving...` 期间多次断电测试。重启只能读到完整旧配置或完整新配置，不应出现时间、星期混合或随机启用。最后一次校验失败但提交已经完成时，重启可能恢复完整新配置，这是允许的。
- 模拟 EEPROM 不可用应先断电，再使用测试夹具断开器件供电/通信，避免带电短接总线。启动应提示 `EEPROM unavailable`，闹钟禁用，试响与主时钟仍能使用；保存应报错。恢复器件后重试，只修改一组，确认其他已保存组不丢失。
- 启动识别无有效记录可显示 `No saved alarms` 或 `Storage invalid`；首次保存后重启应恢复该配置。不要随意擦除整个 EEPROM，工程只预留前 2 KiB。
- 连续切换启用、保存并等待天气/秒钟重绘，观察 I2C1 保存稳定；保存时再触发闹钟，确认停止键响应、无死锁。不要以毫秒循环反复保存，避免 EEPROM 无谓磨损。

EEPROM 使用前 `0x0000～0x07FF` 两个 1024 字节槽；显式版本、递增序号、CRC32、独立提交页和回读校验用于恢复完整配置。其余 62 KiB 不写入。保存只在用户提交时发生，秒钟刷新和响铃不写 EEPROM。

### 5. 保留功能与持续运行

保留原屏幕 RGB/工作队列回归入口，详见 `BOARD_TESTS.md`。实际完整固件确认南京城市与天气、室内温湿度数值、RTC 日期星期和 UART 日志；AHT20 不接或失联仍显示 `--` 并重试，新增闹钟不能修复传感器接线故障。

关闭 AP、重启 ESP、使天气请求超时，检查闹钟仍准时触发；在离线情况下设置和保存仍可操作。恢复网络后校时、南京天气应继续更新。至少持续运行数小时并多次进出菜单、试响、保存、断网恢复，观察 `Workqueue running`、剩余/历史最小 RTOS 堆，无 HardFault、复位、乱码或卡屏。

响铃与贪睡属于运行状态，不在复位后恢复；断主电不发声，重新启动不会补响过去的闹钟。每组记住运行期间最近 32 个已触发日期用于防重；重启或实际修改该组会清空其防重记录，历史更早的日期不保留。
