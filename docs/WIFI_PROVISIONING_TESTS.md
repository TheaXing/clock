# 扫码配网与断电保存验收

本功能面向 STM32F407VE、ESP32-C3 MINI-1 / ESP-AT 4.1.1、BL24C512 和 240×320 屏幕。以下硬件步骤必须实际执行；主机测试或编译成功不等于开发板验收通过。

## 使用流程

1. 启动先读取 EEPROM 保存的网络；没有有效记录时兼容 `app/clock_config_local.h` 的默认网络。
2. 初次连接失败后自动开启 `Clock-Setup-XXXXXXXX` 热点。ESP 初始化时间另计，连接命令最多等待 20 秒。
3. 用手机系统相机扫描屏幕上的 Wi-Fi 二维码加入设备热点。手机提示没有互联网时，选择保持连接。也可使用屏幕上的热点名和密码手动连接。
4. 手机获得地址后，屏幕切换为网页二维码。扫码打开 `http://192.168.4.1/setup`，或在浏览器手动输入该地址。
5. 输入目标 **2.4 GHz** Wi-Fi 名称及密码并提交；名称支持 1–32 字节 UTF-8，密码支持空字符串（开放网络）或 8–63 字节可打印 ASCII。名称不自动去除前后空格。
6. “正在连接”只表示已受理。只有目标连接与 EEPROM 保存均确认后才显示“配置已保存”。热点保留约 15 秒供查看结果，随后返回正常时钟。
7. 之后重启/断电上电会自动使用保存的网络。正常运行短暂掉线会自动重连；更换路由器后重启设备即可再次进入配网。

两个二维码分别用于加入热点和打开网页；不依赖手机自动弹出门户页面。连接目标路由器时热点可能切换信道，手机短暂掉线后可重新加入设备热点并刷新网页。无需重新烧录程序配置网络。

## 硬件用例（均待实板执行）

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 无配置首次启动 | 使用未配置的 EEPROM，且编译默认 SSID 为空 | RTC、传感器及闹钟启动，随后可扫描热点二维码 |
| 原配置不可用 | 关闭原路由器后重启板卡 | 初次连接失败后出现配网入口，不无限等待路由器 |
| Android/iPhone | 分别使用系统相机完成两步扫码 | 二维码完整、白色静区充分；手动连接和输入 URL 也能工作 |
| 正确配置 | 提交可用网络，观察设备和浏览器 | 先连接后保存；成功后热点关闭、天气/校时/OneNET 恢复 |
| 错误密码/SSID | 输入错误密码或不存在的网络 | 显示连接错误，热点/网页继续可用，可再次提交 |
| DHCP 失败 | 目标路由器允许关联但不发地址 | 不保存、不显示成功；恢复 DHCP 后可重试 |
| 特殊字符 | SSID 含中文、空格、引号、逗号、反斜杠；密码含 `+&%=,\"` | 准确连接，无截断或错误转义；超过字节上限明确拒绝 |
| 正常重启 | 完成保存后按 RESET，再整机断电上电 | 自动连接新网络，且不再显示首次配网入口 |
| 换路由器 | 旧网络不可用时重启，配置新网络 | 最新有效配置优先于编译默认值；再次上电使用新网络 |
| 保存失败 | 在候选验证成功时模拟 EEPROM I/O 失败 | 明确提示保存失败，旧配置可恢复，允许重新提交 |
| 保存中断电 | 在不同 EEPROM 写页阶段断电 | 重启只加载完整旧记录或完整新记录，不破坏闹钟/OTA 日志 |
| 结果期 ESP 复位 | 保存成功后、热点关闭前复位 ESP | 主程序恢复已保存的新网络，无需再次输入密码 |
| 配网中 ESP 故障 | 中断 ESP 通信，再恢复 | 不显示假的可用二维码，恢复后重新建立热点和网页 |
| 响铃/菜单抢占 | 停在两种二维码页面时触发闹钟或打开菜单 | 闹钟及按键正常；结束后恢复当前配网步骤 |
| 长时间等待 | 无手机操作保持配网 30 分钟 | 本地功能继续工作，无任务栈溢出；二维码不被时钟或温湿度覆盖 |
| 运行期掉线 | 正常联网后短暂关闭路由器 | 保留时钟页面，自动重连；不突然进入配网页 |
| OTA 试运行离线 | 升级试运行期间让原网络不可用 | 等待配网不阻止本地健康确认；已保存的新网络可供 Boot 恢复使用 |
| OTA 恢复 | 配好新网络后用正常测试流程触发 Boot 恢复 | Boot 连接 EEPROM 网络；保留旧 NVS 静态 IP 时也重新启用 DHCP |
| 路由隔离 | 配网时请求 `/api/alarms`、`/api/ota` | 返回不可用路由，不能经配网模式修改闹钟或触发 OTA |

凭据仅保存在 EEPROM 的 `[0x1000,0x1200)`；闹钟 `[0,0x0800)` 和 OTA `[0x0800,0x1000)` 不变。不要用整片 EEPROM 清空来测试本功能，以免删除真实闹钟。Boot 自身不提供手机配网页；App 镜像损坏且目标网络也不可用时沿用有线恢复。

## 可复现主机验证

在仓库根目录运行 `scripts/test.ps1`。新增测试均在已跟踪的 BSP 目录，不依赖被 Git 忽略的根目录 `tests/`。

- `BSP/WiFi/tests/run_store_tests.ps1`：凭据约束、双槽日志、CRC、断电、应答丢失、损坏及代数回绕。
- `BSP/WiFi/tests/run_lock_tests.ps1`：普通/OTA 构建中真实闹钟服务的 EEPROM 事务锁。
- `BSP/WiFi/tests/run_boot_tests.ps1`：真实 Boot 入口选择已保存网络与默认回退。
- `BSP/WiFi/tests/run_web_tests.ps1`：表单解码、HTTP 分片/路由隔离、手机页面交互。
- `BSP/WiFi/tests/run_state_tests.ps1`：状态机、错误恢复、默认/已保存配置、随机源失败及保存后复位。
- `BSP/WiFi/tests/run_app_tests.ps1`：真实任务的网页/网络调度、显示仲裁和 OTA 健康轮询。
- `BSP/ESP_AT/tests/run_tests.ps1`：真实 AT 驱动、解析器及串口桩，涵盖 AP+STA、超时和连接代次。
- `BSP/QRCode/tests/run_tests.ps1`：真实配网页绘制、边界、静区及独立参考矩阵比对。

构建命令：`scripts/build.ps1`、`scripts/build.ps1 -Configuration Release`、`scripts/build.ps1 -Ota`、`scripts/build.ps1 -Ota -Configuration Release`。构建使用本地凭据配置，但测试日志和网页状态不得输出密码、令牌或密钥。
